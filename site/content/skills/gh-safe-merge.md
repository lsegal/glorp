<section class="skill-hero safe-hero"><p class="eyebrow">External contribution gate</p><h1>Safe first.<br><em>Then merged.</em></h1><p class="hero-copy"><code>gh-safe-merge</code> accepts a pull request nobody on your side owns, typically an outside contribution. It checks that the change is safe and does what it says, then drives it through CI to a merge. It is not a code review.</p><div class="hero-actions"><a class="button primary" href="#install">Install gh-safe-merge</a><a class="button ghost" href="https://github.com/lsegal/glorp/tree/main/.agents/skills/gh-safe-merge">Read the skill</a></div></section>

<section class="process-strip safe-strip" aria-label="gh-safe-merge process"><div><b>01</b><span>Safety check,<br>before anything runs</span></div><div><b>02</b><span>Mark it ready,<br>CI to green</span></div><div><b>03</b><span>Finish<br>superficially</span></div><div><b>04</b><span>Run CI to<br>completion</span></div><div><b>05</b><span>Merge, unless<br>told not to</span></div></section>

<section class="split-section"><div><p class="eyebrow">Not a review</p><h2>No nits. No gatekeeping.</h2><p>Style, structure, naming, and taste are ignored. It never requests changes, never submits a review, and never leaves review-style comments. If the code is safe, works, and does what the pull request says, it is accepted. Acceptance is the default.</p><p>It finishes a pull request rather than rewriting it. The only changes it makes are superficial: resolving merge conflicts, formatting, auto-fixable linter passes, a changelog entry, and README or docs updates the change plainly requires. Anything more substantive goes back to the author.</p></div><div class="github-mock" aria-label="Illustrative GitHub pull request card"><div class="mock-top"><span class="gh-mark">◉</span><span>Pull requests · from a fork</span><span class="mock-dots">•••</span></div><div class="mock-body"><span class="merged-pill">Merged</span><h3>Add a retry to the upload step</h3><p>first-time contributor · checks passed</p><div class="mock-comment"><b>gh-safe-merge</b><span>Safety check passed. Held workflow runs approved, changelog entry added, CI green, squash-merged.</span></div></div></div></section>

<section class="workflow-section quiet-workflow"><p class="eyebrow">Unsafe until cleared</p><h2>The safety check gates everything.</h2><p class="section-lede">Running untrusted code is the risk itself, so nothing from the pull request is built, tested, installed, or run until the check passes. CI is never unblocked before it. The check reads the description, the full diff, and every commit for:</p><div class="callout-grid"><article><strong>Intent</strong><p>The code does what the pull request says and nothing beyond it. No unrelated behavior rides along.</p></article><article><strong>Security</strong><p>No new injection, exfiltration, privilege, or unsafe-default surface.</p></article><article><strong>Malicious behavior and backdoors</strong><p>No hidden functionality, covert network calls, credential harvesting, obfuscated payloads, or unexplained binary blobs.</p></article><article><strong>Supply chain</strong><p>New dependencies are legitimate, spelled correctly, and pinned. Install scripts, build hooks, and CI workflow changes get extra scrutiny, above all anything that reads secrets or widens permissions.</p></article><article><strong>Licensing</strong><p>No code or asset under an incompatible license, and no unattributed copied code presented as original.</p></article><article><strong>General properness</strong><p>The contribution is what it claims to be, not spam, vandalism, or nonsense dressed up as a change.</p></article></div><p>If the author pushes new commits mid-run, the check runs again on them before anything else happens.</p></section>

<section class="workflow-section quiet-workflow"><p class="eyebrow">Three outcomes</p><h2>Merged, handed back, or closed.</h2><div class="decision-map safe-outcomes"><div class="decision-answer"><b>Safe and working</b><span>CI green, merged with no comment. The merge is the acceptance.</span></div><div class="decision-stop"><b>Merely incorrect</b><span>One comment mentioning the author says what is wrong. Not merged, not closed.</span></div><div class="decision-closed"><b>Malicious</b><span>Closed at once with a comment mentioning the author. Its code never runs.</span></div></div><div class="callout-grid"><article><strong>Incorrect is not malicious</strong><p>Behavior that contradicts the description, a substantive problem, or tests failing on the pull request&rsquo;s own code goes back to the author. Closing is reserved for bad faith.</p></article><article><strong>Holds are honored</strong><p>A do-not-merge label, hold wording in the thread, or <code>and do not merge</code> stops it short of the merge, with one comment saying it cleared the check and CI and naming the hold.</p></article><article><strong>Drafts are finished, not held</strong><p>A draft that clears the safety check is marked ready for review and carried on to the merge. One that fails the check stays a draft.</p></article></div></section>
